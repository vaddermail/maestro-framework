# Maestro Framework Inventory

Complete manifest of every file in the framework, one line per file.
**Rule:** every framework **content** file (`.md`, `.template`, `.sh`) is here; every path referenced in another document exists here. Repository infrastructure files (`.github/`, `.gitignore`) live outside the inventory and the gate.
When adding/removing files (see `playbooks/add-an-agent.md`), update this inventory in the same step.

## Root

- `README.md` — front door: what the framework is, navigation map, how it is used.
- `MANIFESTO.md` — philosophy and non-negotiable principles of AI-assisted development.
- `START-HERE.md` — bootstrap of a new project: instructions for the human and for the first AI session.
- `CONTRIBUTING.md` — how contributions flow: field reports up, curated releases down (the improvement circuit, adapted to open source).

## _meta/

- `_meta/INVENTORY.md` — this file.
- `_meta/STYLE-GUIDE.md` — writing and formatting conventions for all documents.
- `_meta/VERSION.md` — framework version and change log of the framework itself.
- `_meta/verify.sh` — self-check of internal consistency (inventory↔disk, cross-references, agent spec sections, language); the framework's own gate.
- `_meta/DO-NOT-DISTRIBUTE` — list of upstream-only files excluded from the release ZIP (the upstream→copies confidentiality lever).
- `_meta/verify-project.sh` — the PROJECT's gate: foundation, trail of closed phases, fresh memory, genesis, copy integrity.
- `_meta/test-project-gate.sh` — exercises the project gate against synthetic projects (compliant, deviant, unreadable phase, unfilled genesis); runs in CI and inside the release artifact.
- `_meta/FORBIDDEN-TERMS` — names that must never travel in what you distribute; read by check 14 of `_meta/verify.sh`. Ships empty.

## core/ — the operating system

- `core/orchestrator.md` — the Orchestrator: who calls whom, when, dependencies, approvals, failure recovery.
- `core/lifecycle.md` — the product's F0–F9 phases, from idea to continuous evolution, with gates between phases.
- `core/artifact-protocol.md` — information contract between agents: the `product/` tree, formats, owners, consumers.
- `core/question-engine.md` — how the user is asked: batches, context, options with trade-offs, defaults, answer log.
- `core/decision-engine.md` — how technical choices are decided: criteria matrix, arbiters, mandatory ADR, closed decisions.
- `core/quality-gates.md` — gates between phases: definition of done, who validates, what blocks, human approval.
- `core/project-memory.md` — memory in local files: STATE.md, decisions, logs; handover between sessions/people/tools.
- `core/model-routing.md` — routing of AI models per task (Top/Standard/Economy/Mechanical tiers + effort), costs under control.
- `core/extensibility.md` — how to add agents, modules, workflows and loops without changing existing ones.
- `core/glossary.md` — framework terms (agent, artifact, gate, loop, guardian, arbiter, phase, ADR, …).
